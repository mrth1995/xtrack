## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps, status marker spacing, banner close-button spacing |
| sm | 8px | Compact row gaps, banner text stack, dropdown item dividers |
| md | 16px | Page gutters, banner padding, offline notice padding |
| lg | 24px | Separation between install/offline notices and Quick Add sections |
| xl | 32px | Page top padding and large vertical breathing room |
| 2xl | 48px | Major sheet/offline-shell spacing when content is centered |
| 3xl | 64px | Reserved for full-page fallback states only |

Exceptions:
- Minimum tap target remains `44px` for dismiss controls, install actions, menu items, and realtime row links.
- Primary buttons remain `48px` high where Android install prompt action buttons are available.
- Existing Quick Add numpad keys remain `56px`; category tiles remain `64px`. Phase 4 must not resize them.
- Realtime row highlight must not change row height, padding, border width, or layout.

## Typography

Use exactly these four sizes and exactly two weights (`400`, `600`) in Phase 4.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 or 600 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 48px | 600 | 1.1 |

Usage:
- `48px` display is reserved for the existing Quick Add amount only; do not use display type for PWA notices or realtime labels.
- `20px` heading is reserved for section headings such as `Today`.
- `16px` body is used for row content, menu items, install guidance body copy, and offline notice body copy.
- `14px` label is used for metadata, secondary links, banner headings, status text, and errors.

Source notes: sizes and weights come from `src/app.css`, `src/routes/(app)/+page.svelte`, `ExpenseList.svelte`, `Numpad.svelte`, `CategoryGrid.svelte`, and the Phase 2 UI spec.

## Color

No new brand colors are introduced in Phase 4.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F3EB` / `--color-bg` | App background, cached app shell background, full-page fallback states |
| Secondary (30%) | `#E7DED0` / `--color-surface` | Install guidance shell, offline notice shell, list dividers, controls, cards |
| Accent (10%) | `#176B5D` / `--color-accent` | Install banner heading/action, Android install CTA, realtime new-row highlight border/background tint, success/ready status emphasis |
| Destructive | `#B9382F` / `--color-destructive` | Failed sync/offline error text and destructive actions only |

Accent reserved for:
- Install guidance heading or actionable install button.
- Android `Install app` CTA when `beforeinstallprompt` is available.
- Realtime partner-row highlight, as a subtle temporary tint or 2px inset/accent border that fades out.
- Existing primary actions from prior phases, such as `Save note` and `Save changes`.

Accent is not used for every tappable element, list row, numpad key, or category tile background. Offline/stale notices use secondary surface plus muted text; they only use accent if the state is positive or actionable.

| Error state | `You're offline. We'll show saved data and sync when you're back online.` |
| Destructive confirmation | None in Phase 4. No destructive PWA or realtime action is introduced. |

Additional Phase 4 copy:

| Surface | Copy |
|---------|------|
| iOS install guidance heading | `Add to Home Screen` |
| iOS install guidance body | `Tap Share, then Add to Home Screen.` |
| Android install guidance heading | `Install xtrack` |
| Android install guidance body | `Add xtrack to your Home Screen for faster expense logging.` |
| Android install CTA | `Install app` |

| Standalone/session restore | `Restoring your session...` |

- Install guidance is instructional, not promotional.
- Offline copy must be honest about stale data without blocking Quick Add.

## Interaction Contract

### Install Guidance

1. The banner appears only in the authenticated app shell and never in standalone display mode.
2. iOS Safari shows manual instructions: heading `Add to Home Screen`, body `Tap Share, then Add to Home Screen.`
3. Android/Chromium with `beforeinstallprompt` available shows heading `Install xtrack`, body `Add xtrack to your Home Screen for faster expense logging.`, and a `Install app` CTA.
4. The install CTA must be `48px` high, accent-filled, and only shown when the browser exposes an install prompt event.
5. Dismiss remains a snooze, not a permanent opt-out. The dismiss button keeps a `44px` touch target and an accessible label.
6. The banner must not appear after installation, in standalone mode, or during the standalone session restore screen.

### Offline Shell Notice

1. Offline app open serves the cached shell first.
2. If the app is offline but usable, show the compact notice: `You're offline. We'll show saved data and sync when you're back online.`
3. If the app is showing cached/stale data, use: `Showing saved data. New expenses may appear when you're back online.`
4. The notice is non-blocking. Users can still use Quick Add; local queued status rows handle save feedback.
5. The notice disappears automatically when the app returns online and a refresh/sync attempt completes.
6. Do not use a modal, full-screen takeover, snackbar overlay, or bottom sheet for normal offline state.

### Realtime Today Inserts

1. Subscribe only while the Today screen or signed-in app context has a valid `householdId`.
2. Incoming partner expense appears in the Today list immediately and sorts by `spent_at` using the existing row order.
3. Newly inserted partner rows receive a temporary highlight for `1200ms`, then fade back over `400ms`.
4. Highlight style: keep the row transparent layout, add a subtle `--color-accent` tint or inset border. Do not animate row height, position, amount text size, or category layout.
5. Own inserts with a `client_id` already present locally are skipped with no visible feedback and no redundant list re-render.
6. If an incoming server row matches a local queued/syncing row by `client_id`, replace that row silently, clear sync status, and preserve row position where possible.
7. Failed queued rows keep their existing failed status and destructive color until sync logic resolves them; realtime must not mask failures with a highlight.
8. No toast, sound, badge, or notification is added for realtime in Phase 4.

### Accessibility And Motion

1. Install and offline notices use `role="status"` or `aria-live="polite"` only when the message appears after initial render. Do not repeatedly announce stable banners.
2. Realtime row highlight is decorative; the inserted row content itself must remain navigable and readable.
3. Respect `prefers-reduced-motion`: skip fade animation and show at most a static 1200ms tint before returning to normal.
4. All controls remain keyboard reachable and focus-visible.
